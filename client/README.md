# Original Cocos client recovery

This is a development client recovered from the supplied APK. It runs the original Cocos Creator 2.4.7 scenes, prefabs, textures, fonts, audio, and animations. It is not a finished standalone game release. The current server has 21/21 approved rulebooks and 21 production-registered engines, with the 189/189 automatic complete-room matrix passing; this does not claim original-server equivalence or completed physical-device acceptance.

Current service: `http://192.168.1.17:3000/client/`; admin: `/admin/`. Formal APK: `client/android/doushisi.apk`, SHA-256 `eb81fcdd088dbfc00275fe8a36912692b8a9534d51e36789f9ffae24b4522fe8`; releaseSubject `53bdaf077c9d101ba7f8a3add8a2e3a6f06d3ddc6c3d8995a7a8dd8b0fef5c14`. `localReady` and `releaseReady` remain false. The only remaining release blocker is physical-device acceptance on two different authorized Android phones over the same LAN; emulators do not count.

## Contents

- `public/`: browser inspection build using the official Cocos 2.4.7 engine and original compiled bundles.
- `android/doushisi.apk`: signed native Android development APK, package `net.doushisi.standalone`, using the original native Cocos runtime.
- `android/native/`: new platform GPS adapter in smali.
- `android/recovered-apktool.zip`: exported recovered Android project, excluding intermediate build output and signing secrets.
- `validation/`: automated browser evidence and retained-resource hash audit.
- `recovery-manifest.json`: engine and original controller provenance.

The original Creator editor project, original `.meta` files, Java source, and server source were not supplied. The recoverable Android project is an Apktool project generated by the build script, with original DEX code plus narrow smali patches. Do not describe this as the missing original Creator source or a Gradle source reconstruction.

## Local preview

Start the project server using the root README. The original client is served at `http://127.0.0.1:3000/client/`, and uses the v2 original-protocol WebSocket endpoint `/ws/original`. Accounts are created through the original registration panel. New users have zero beans.

The LAN address is read from `.local/runtime.json` (`apiBase`) by the local tooling. Read the current value with:

```powershell
(Get-Content .local/runtime.json -Raw | ConvertFrom-Json).apiBase
```

Override it with `DOUSHISI_API_BASE` or an explicit `-ApiBase`/`CLIENT_URL` value when rebuilding or running an acceptance check:

```powershell
$env:DOUSHISI_API_BASE = 'http://<current-lan-host>:3000'
```

The LAN APK does not need ADB reverse. Formal physical-device acceptance prohibits both `adb reverse` and `adb forward`; the two phones must reach the server directly over the same LAN. The following loopback commands are development-only and must not be used for acceptance:

```powershell
adb reverse tcp:3000 tcp:3000
adb install --streaming -r client/android/doushisi.apk
adb shell am start -n net.doushisi.standalone/org.cocos2dx.javascript.AppActivity
```

For a remote server, rebuild with `-ApiBase https://your-server.example`. Use a trusted TLS certificate and a stable signing key. Browser configuration lives in `public/runtime-config.js`; it is public configuration and must never contain administrator credentials.

## Reproduce the browser build

Extract the original APK as a ZIP. Keep its `assets/` directory intact. Obtain `https://github.com/cocos/cocos-engine` tag `2.4.7`, commit `f7d50d63228ec3047fe054a2d1e1535e90da2bd1`, install its dependencies, and run `gulp build-html5-dev`. Then, from the project root:

```powershell
node tools/client-prepare.mjs C:/path/to/extracted-apk/assets C:/path/to/cocos-engine/bin/cocos2d-js.js
node tools/client-audit-assets.mjs C:/path/to/extracted-apk/assets/assets
```

The script re-copies retained bundles and checks exact controller fingerprints before patching. Never edit generated `public/assets/*/index.js` by hand; change `client-prepare.mjs` and rerun it. `public/standalone.js` is the shared client adapter.

## Reproduce the native APK

Requirements: PowerShell 7, Node.js 24, Java 17, Apktool 3.0.3, Android SDK Build Tools 35.0.0, and a private signing keystore. The browser recovery step must finish first. `client-keygen.ps1` can generate a keystore; provide its password through `DOUSHISI_KEYSTORE_PASSWORD`, never a source file or command argument.

```powershell
$env:DOUSHISI_KEYSTORE_PASSWORD = '<read from your secret store>'
./tools/client-native-build.ps1 `
  -OriginalApk C:/path/to/original.apk `
  -JavaHome C:/path/to/java17 `
  -ApktoolJar C:/path/to/apktool.jar `
  -BuildTools C:/path/to/android-build-tools `
  -KeyStore C:/private/doushisi.jks `
  -ApiBase https://your-server.example
```

The script writes the decoded native project and intermediate APKs into the workspace `work/client-native-build`, then verifies the final APK signature. Keep the keystore and password in an encrypted backup: future application updates require the same signing key. The local development signing material is outside this deliverable and is protected using the current Windows account.

After building, run `pwsh -NoProfile -File tools/client-export-native.ps1` to refresh `android/recovered-apktool.zip`. It is an Apktool reconstruction, not the missing Creator editor project.

## Client changes

Original retained scenes and binary assets are unchanged. The adapter opens the existing account login panel, removes the approved entrypoints, disables advertising and SDK startup, isolates local storage, and disables the original hot-update network flow. It preserves the native Cocos runtime rather than embedding the browser build. The self-hosted server supplies `/client/standalone/default-avatar.png` for accounts without a profile image; the original avatar frames and positions are retained. The PNG is generated from the existing Lucide UserRound icon, with its license alongside it. Re-render it with `tools/client-default-avatar.mjs` and `SHARP_MODULE` pointing to Sharp when needed.

The original friend list now reuses rows on refresh, polls every ten seconds while open, and clears removed rows. Invitation rewards and recall controls are hidden. The hall coin bitmap retains its original bytes; an exact crop hides the removed top-up area without shifting the score or stretching the image. Long nicknames shrink within the existing header area. `tools/client-social-validate.cjs` checks the original layout with controlled friend data at two viewports; it needs `PLAYWRIGHT_MODULE` and `SHARP_MODULE` and is not real-game acceptance.

`tools/client-hall-balance-validate.mjs` checks the retained hall balance region at two browser viewports. It confirms the original label is hidden, the replacement uses the retained 156px left bitmap segment, the retired store listener is absent, a real canvas click keeps the hall background, and a simulated legacy callback is restored immediately. The Android counterpart is recorded in `validation/native-hall-balance-tap-report.json` and `validation/native-hall-balance-tap.png`.

The dissolve window now finds voters by user ID, preserving the original layout when occupied seats are not contiguous. Run `tools/client-vote-validate.cjs` with the same `PLAYWRIGHT_MODULE` setting to reproduce `validation/dissolve-report.json` and its screenshot covering occupied seats 1 and 3 and vote cancellation.

Protobuf message numbers and HWFR framing are retained. The v2 JSON extension in field 60000 restores decimal strings before original controllers receive messages. Login credentials are never printed or persisted as plaintext. The native location adapter requests Android location permission and uses `LocationManager`; live GPS accuracy still requires device testing.

The location bridge now requests coarse/fine permissions together, isolates GPS/network failures, and reads the newer system location without an application-level coordinate cache. `tools/client-location-emulator.ps1` builds a separate instrumentation APK signed with the game key and runs eight synthetic-location cases against the installed game bridge. It verifies active listener registration, approximate permission handling, revocation, disabled providers and newest-fix selection, then restores and re-reads the emulator settings. See `validation/location-emulator.json` and `docs/native-capabilities.md`. These checks do not validate physical GPS accuracy, the permission-dialog UI, room coordinate exchange or audible voice output.

The retained `LocationUI` clears expired distances when a location notification arrives while open, and shows avatars by occupied seat (including seats 1 and 3). Its layout and assets are unchanged. `tools/client-location-validate.cjs` verifies these states at two viewports using controlled distances; evidence is in `validation/location-fixtures/`. The server invalidates only the authenticated room member's cached point when an enter request explicitly reports the original `0,0` unavailable value.

Protected original requests (23/53/121/125) now append a unique command ID and room UUID; game actions also bind the round and state version. A repeated visible game action reuses its ID, and only its matching acknowledgement clears the pending request. The client advances the game cursor when the original animation queue delivers a state message, never when a heartbeat or action acknowledgement first arrives. Rejections and unacknowledged operations restore the original table snapshot instead of leaving optimistically moved cards missing. The original autoplay response now affects only the local player's model. These transport controls do not provide regional rules or prove completed gameplay.

Original chat uses type 1 with `mutualFaceId` for twelve phrases, type 2 with the original asset name for fifteen expressions, and type 3 for eleven seated interactions. The server validates these exact ranges and supplies the authenticated sender identity. Expression loads cannot overwrite newer requests, and interaction loads and delayed movement callbacks reject stale rooms or player models. `tools/client-chat-validate.cjs` checks original button handlers over two browser clients, including 24 gendered audio clips, Spine timeline progress and cleanup. `tools/client-chat-lifecycle-test.mjs` covers callback races; see `docs/original-chat-v1.md`. Browser playback is not Android speaker acceptance.

## Verification and remaining work

`public/standalone-replay.js` reuses the original CommonRePlay controller with authenticated paged viewer projections. It supports pause, speed, seek, restart and exit, suppresses live writes, restores self autoplay on seeking and preserves position after successful reauthentication. `tools/client-replay-test.mjs` contains 38 isolated tests. `tools/client-replay-validate.cjs` validates synthetic original packet projections at two viewports; its images and report are in `validation/replay-fixtures`. These fixtures do not implement regional rules or represent real completed games.

Run `tools/client-validate.mjs` and `tools/client-e2e.mjs` with `PLAYWRIGHT_MODULE` pointing to an installed `playwright-core` package and Microsoft Edge installed. The first script uses local bootstrap credentials from `.local/local-access.json`. The second registers fresh zero-balance accounts through the original UI. It checks host creation, six-digit room joining, original seat placement, ready notifications, rejection before fees, reload reconnection, and pre-game room closure. Neither script plays a completed game.

`tools/client-room-options-e2e.mjs` is a focused browser check for the standalone-only room controls. It verifies the required empty base-bean input for an original configuration without `basicTimes`, rejects blank and zero values before a request leaves the client, shows the empty `2/3/4` selector for area 14, and creates a waiting room with the exact V2 `baseBeans` and `playerNum` metadata. It writes `validation/manual-room-options-report.json` and `validation/manual-room-options-14.png`.

The same room-options check verifies the placeholder and entered base-bean text (`0.125`) in the Cocos form. The native confirmation is in `validation/native-base-beans-input-report.json`, with both focused and filled screenshots.

The LAN update replaces the independent overlay with bound EditBox `textLabel` and `placeholderLabel`. The keyboard test types `0.123456789012` and verifies blur without duplication or loss; Android evidence is `validation/local-native-input-verified.png`, captured after entering `0.125` and closing the system input with Done.

The automatic regional rule, room-matrix and replay work is complete, but the client still requires formal physical-device acceptance on two different authorized Android phones for GPS/voice behavior and the full user workflow. That evidence is separate from original-server comparisons, which are not claimed here. Both bitmap score fonts include a decimal point and controlled score/animation/result/record fixtures pass at two viewports; see `validation/decimal-fixtures/`. Do not distribute this APK as the final accepted version.

Native startup handles Cocos URL shims that lack an origin parser and loads Decimal through its global export without overwriting it with JSB's empty `require` return value. The original Java `postException` upload is disabled at the native bridge, including exceptions before the game adapter starts.

`validation/native-report.json` records the Android 14 emulator run: native login, process restart, original room creation, browser/native interoperation, and restoration of the same waiting room after restart. The original runtime emits a nonfatal texture-format warning during table sprite initialization, which remains listed in the report.

That report refers to the earlier APK. `validation/native-current-report.json` binds the latest APK and recovered archive to its installed hash, startup screenshot and current-process checks. Reproduce this narrower smoke check with `pwsh -NoProfile -File tools/client-native-smoke.ps1`. It is not completed-round or full network-isolation acceptance.
