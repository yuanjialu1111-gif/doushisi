## 2. 关键设计

### 2.0 红线怎么保证

| 红线 | 怎么保证 |
|---|---|
| 1 不推送、不部署 | 只在本机做、本机提交；发布用现有 `tools/release-test-server.sh`，你点运行 |
| 2 不读线上玩家数据 | 只用本机 PGlite 和测试账号 |
| 3 不手改原版编译包 | 现有哈希扫描：`client/public/assets/*/index.js` 必须等于基线；改动只在 `standalone.js` |
| 4 私聊和牌桌都不能打字 | 服务端只收编号（常用语编号、表情编号、邀请卡），收到 `message` 文字一律拒；自动测试覆盖 |
| 5 距离只给档位 | 大厅接口只回档位字符串，不回米数和坐标；测试断言响应里没有数字距离 |
| 6 只用 `kill <PID>` | 停服务用预览工具或记下的 PID |
| 7 不扩范围 | 只做 S1–S7；新想法记进 `docs/plan/待确认.md` |

### 2.1 去地区（S1）

- **服务端**：登录时 `connection.region` 一律设成新津那一项，不看客户端发来的、也不看库里存的；地区列表请求回只有新津的一项。`original_protocol_regions` 老值不删。
- **版本配置**：新加「界面显示的玩法」，只有新津（玩法编号 4）；`retainedAreaTypes`（服务端接受的玩法）不变，所以老房间、战绩、回放都不受影响。
- **客户端**：藏地区按钮、大厅左侧玩法栏、开房页的玩法列表；开房直接用新津。
- **后台**：大厅桌模板的玩法下拉只给新津；服务端创建模板时也只收新津。已有的其他玩法模板设成停用（你在后台点，或 M1 里给一个一次性迁移，见第 8 节）。

### 2.2 大厅 A2 卡片（S2）

- **服务端** `lobby.ts`：每个座位多带 `sex`、`uid`（对外的数字 ID）；每张有人的桌都算距离档位（以前只在「附近」栏算）：取桌上离我最近的人，没定位就不显示。
- **客户端** `lobbyCard()` 重写：Cocos Graphics 画玻璃底板和俯视绿桌，头像用圆角方形遮罩，昵称条压在头像底部。点头像弹信息卡，点别处关闭。
- 一屏卡片数和上轮一样按窗口宽度算，16:9、16:10、4:3 都截图核对。

### 2.3 加好友（S3）

- **搜 ID**：`GET /api/social/search?uid=`，按对外数字 ID 查，每人每分钟 10 次（限频插件按令牌计）。查到回头像、昵称、性别、是否已是好友 / 已申请。
- **申请**：`friend_requests` 一行一个申请，状态 待处理 / 同意 / 拒绝 / 过期。
  - 检查：不能加自己、已是好友、对方或自己满 200 人、今天已申请 20 个、24 小时内被对方拒过。
  - 同意：一个事务里写两条 `friends`（双向）、改申请状态。
  - 过期：查询时把超过 7 天的待处理当过期，每小时清理一次。
- **停自动加**：删掉 `rooms.ts:485` 结算后写 `friends` 的那段。`friends.first_room_id` 现在是必填，同意申请时没有房间号，迁移里改成可空。
- **最近同桌**：从 `room_members` 查最近 7 天同桌过的人，最多 30 个（AI 暂定），排除已是好友的。
- **好友列表**：多带在线状态：离线 / 空闲 / 打牌中。在线状态从原协议连接表取（`original-wire.ts` 的 `online`），通过一个小函数交给好友服务，不把连接表传出去。

### 2.4 私聊和邀请入座（S4）

- **私聊**：`POST /api/social/messages`，`kind` 只能是 `phrase`（常用语编号）、`face`（表情编号 0–14，原版 15 个）、`invite`（邀请卡）。不是好友不能发。常用语用原版牌桌常用语，再加 6 句约局用语（来一把？/ 马上来 / 等我一下 / 今天不打了 / 谢谢 / 好的，AI 暂定）。
- **未读和轮询**：`GET /api/social/pulse` 回未读申请数、未读消息数、待处理邀请。客户端在大厅、好友页、牌桌开局前每 5 秒拉一次；牌局进行中不拉。
- **邀请**：
  - 邀请方必须在一个还没开局、有空座的房间里；被邀请方必须是好友、在线。
  - 同一好友 60 秒一次；邀请 60 秒有效。
  - 被邀请方空闲：轮询拿到后弹窗，60 秒倒计时；打牌中：不弹，邀请卡进「消息」。
  - 同意：服务端再查一遍（邀请没过期、房间还在、有空座），回房号；客户端走原来的「输房号进房」，门槛和自己进房一模一样。
  - 结果写回邀请卡：已入座 / 已拒绝 / 已过期 / 桌已满。
- **清理**：消息超过 30 天每小时清一次。

### 2.5 大厅首页（S5）

- **「进入大厅」卡**：原卡片字是画在图里的。用脚本照原图重画一张，字改成「进入大厅」，运行时替换这张卡的贴图，位置大小不变。
- **设置小窗**：M1 先登录本机网页实测，找出偏的原因（怀疑是上轮藏了底部按钮，按钮挪了，小窗还按旧位置弹），再改成每次弹出时按设置按钮的实际位置摆。16:9 和 4:3 各截图。

### 2.6 个人资料（S6）

- **战绩**：从 `rounds`（已结算）的结算结果取我每局得分：对局数 = 局数，总胜局 = 得分大于 0 的局数，胜率 = 胜局 ÷ 局数（四舍五入到整数 %）。原协议的登录回包和个人信息回包（`original-wire.ts:498 / 691`）都换成真实值。
- **勋章**：`account_medals` 记谁在什么时候点亮了哪个。
  - 局数类（前途无量 10 局、百胜王 100 胜、千胜王 1000 胜）：每局结算后检查。
  - 豆子类（富甲一方 1 万、百万富翁 100 万、千万富翁 1000 万）：结算后、登录时、打开资料时检查当前豆子，到了就点亮。点亮后一直亮。
  - 条件从后台参数读。
- **界面**：`patchPersonWindow` 把周卡圆圈和头像框两块换成勋章区，用原版 6 个勋章图标，没点亮的变灰并显示进度。

### 2.7 互动表情（S7）

- **图**：`tools/extra-art.mjs` 用 SVG 画 8 张（风格对齐原版表情：圆润、描边、高光），本机 Chrome 无头渲染成 PNG。先把 8 张图发你看，你点头再接入。
- **服务端**：`rooms.ts:635` 互动表情编号从 2–12 放宽到 2–20。只把 13–20 转发给声明了「支持新表情」的连接（新接入层登录时带一个标记），旧客户端收不到。
- **客户端**：表情面板在原 12 个后面接 8 个，照原版翻页；收到 13–20 时不走原版 `prefab/com_prop_` 加载，改用图片 + `cc.tween` 动画（从发起人头像飞到目标头像、放大、抖动、淡出）。

### 2.8 后台参数（S3、S4、S6）

- `app_settings` 存一份参数（JSON），服务端启动时带默认值，改了立刻生效。
- 后台「参数」页：好友上限、每天申请数、申请过期天数、被拒冷却小时、搜 ID 每分钟次数、邀请有效秒数、消息保留天数、6 个勋章条件。权限和大厅桌模板一样（豆子管理员）。改动写审计记录。

## 3. 库表设计（迁移 011，只加不删，旧版本程序也能跑）

| 表 | 关键字段 | 说明 |
|---|---|---|
| `friend_requests`（新） | `id`、`from_id`、`to_id`、`status`（pending/accepted/rejected/expired）、`created_at`、`decided_at` | 同一对人同时只有一条待处理（部分唯一索引）；按 `to_id, status` 建索引 |
| `friend_messages`（新） | `id`、`from_id`、`to_id`、`kind`（phrase/face/invite）、`ref`（编号或邀请 ID）、`created_at`、`read_at` | 不存文字；按 `to_id, read_at` 建索引；30 天清 |
| `room_invites`（新） | `id`、`from_id`、`to_id`、`room_id`、`created_at`、`expires_at`、`result` | 邀请卡的状态；同一对人 60 秒限一次靠这张表查 |
| `account_medals`（新） | `account_id`、`medal`、`unlocked_at` | 主键 (account_id, medal) |
| `app_settings`（新） | `key`、`value`（jsonb）、`updated_at`、`updated_by` | 后台参数 |
| `friends` | `first_room_id` 改成可空 | 同意申请时没有房间号；老数据不动 |

所有归属（谁申请、谁发消息、谁邀请）都从登录令牌取，不信请求参数。
