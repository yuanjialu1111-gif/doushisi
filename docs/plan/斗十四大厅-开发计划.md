## 2. 关键设计

### 2.0 红线怎么保证

| 红线 | 怎么保证 |
|---|---|
| 1 不写密钥，签名钥匙不进源码 | 钥匙放 `~/.doushisi-signing/`（源码目录外），打包脚本只读环境变量；加扫描：源码里出现 `.jks`/`.keystore`/私钥头即失败 |
| 2 不推送不部署 | 只在本机做；发布做成一条脚本，用户点运行 |
| 3 不读线上玩家数据 | 只用本机 PGlite 和测试账号 |
| 4 不手改原版编译包 | 扫描：`client/public/assets/*/index.js` 的哈希必须等于原始哈希，改动只在 `client-prepare.mjs` 生成的产物里 |
| 5 照片去拍摄位置 | 服务端一律重新编码（不是只删字段）；测试：上传带 GPS 信息的照片，下载回来检查没有元数据 |
| 6 只用 `kill <PID>` | 停服务用预览工具或记下的 PID |
| 7 不扩范围 | 只做 R1–R11；冒出来的新想法记进 `docs/plan/待确认.md` |

### 2.1 资料与头像（R6、R7、R8、R9）

- **登录后检查**：接入层登录成功后调 `GET /api/me/profile`；资料没设就弹出资料设置浮层，盖住大厅不能关。服务端同时兜底：资料没设的人开房、进房一律拒绝（错误码 `PROFILE_REQUIRED`），绕过客户端也没用。
- **资料设置浮层**：运行时拼界面，贴图用原版大厅素材。
  - 头像：网页版用系统文件选择框（手机浏览器会给出「拍照 / 相册」）；安卓调原生拍照和选图（M5）。
  - 选好的图先在客户端缩到 512px 再上传，省流量。
  - 昵称输入复用 CommonEditUI；性别用两个单选。
- **头像上传** `POST /api/me/avatar`：
  - 请求体单独放宽到 5MB，其余接口仍是 64KB。
  - 只收 JPEG/PNG/WebP，用 sharp 重新编码成 256px JPEG，不带任何元数据。
  - 按内容算哈希，地址形如 `/media/avatars/<账号ID>-<哈希>.jpg`。换图就换地址，Cocos 不会显示缓存的旧图（R7 AC2）。
  - 失败（太大、不是图片）返回原因，原头像不变（R9 AC4）。
- **出图** `GET /media/avatars/:file`：不需要登录（Cocos 加载图片带不了令牌），地址里有哈希猜不到。已驳回的返回灰色默认头像。
- **6 处出口**：桌上成员、登录回包、好友、个人信息、回放、REST 好友，统一改成调 `avatarUrl(账号)`；性别不再一律填 0。
- **昵称**：2–7 字，去首尾空格后不能和已设好资料的人重名（数据库唯一索引兜底），查本地敏感词表；30 天内只能改一次，提示下次可改日期。
- **驳回**（后台）：头像驳回 → 状态 `rejected`、出图变灰、下次登录必须重传；昵称驳回 → 下次登录必须重填。都写进 `audit_events`（谁、什么时候、驳回了哪张图）。
- **老账号**：上线后第一次登录同样弹资料设置（R6 AC2）。昵称可以沿用原来的，只要不和别人重名。

### 2.2 大厅与系统桌（R1、R2、R4、R5）

- **列表** `GET /api/lobby/tables?variant=…`：
  - 返回公开桌：玩法、底分、局数、人数、已坐玩家头像昵称、附近档位（有位置时）、列表版本号。
  - 接入层在大厅界面可见时每 2 秒拉一次；版本号没变时服务端只回「没变」，几乎不占流量。满足「3 秒内看到变化」（R1 AC1）。
  - 私人房一律不返回（R1 AC3）。
- **系统桌**：
  - 每个模板（玩法、底分、人数、局数、常驻空桌数、门槛倍数）由后台配。
  - RoomScheduler 每几秒检查一次：空桌少于设定数就补开（R2 AC1）；坐下超过清座时限（默认 10 分钟，后台可改）还没开局的，清座并通知本人，不扣豆（R2 AC4）。
  - 房主是一个内置的系统账号，不能登录。系统桌有人开局前离开只空出座位，不关桌（R2 AC2）。
  - 打完设定局数就关闭这间房；补桌逻辑会开一张新空桌顶上，大厅看起来就是「桌子回到 0 人」（R2 AC3）。
- **入座**：点桌子 → 接入层拿到房号 → 走原版输房号进房。服务端进房时查门槛：豆子 < 底分 × 倍数就拒绝，并提示还差多少（R5 AC2）。
- **快速开始** `POST /api/lobby/quick-start`：
  - 在当前玩法里找有空位、门槛够的桌子，人最多的优先；没有就按模板开一张。
  - 返回房号，后面和点桌子一样。
  - 哪一档门槛都不够时提示「豆子不足」（R4 AC1、AC2）。
- **房费**：公开桌一律 AA，沿用「第一局全员准备后才扣」（R5 AC1）。
- **并发**：两人抢最后一个座位时，用现有进房事务加行锁，只有一人成功，另一人提示「桌子已满」。

### 2.3 玩家桌公开 + 房内去定位（R3、R11）

- 开房选项加「公开到大厅」（默认不勾）；勾了就把房费强制改成 AA，并在界面上提示（R3）。
- 玩法目录去掉「开启GPS定位」。服务端忽略老房间里的 `openGps`，删掉进房/重连的坐标检查和牌桌距离推送（R11 AC2、AC3）。
- 接入层隐藏牌桌定位按钮，不弹距离面板（R11 AC1）。

### 2.4 附近的桌子（R10）

- 接入层进大厅时取一次位置，用 `POST /api/me/location` 把坐标放在请求体里发（不放网址）；之后每 2 分钟更新一次。
- 坐标只放服务端内存并记时间，超过 10 分钟就不算；不写数据库，重启就清。
- 服务端对每张有人的桌子，算你和桌上最近一个已坐玩家的距离，只回档位：1 公里内 / 5 公里内 / 同城（50 公里内）/ 更远。不回米数和坐标（R10 AC1）。
- 空桌不进「附近」；你没有位置时，接口不回附近档位，界面不显示「附近」一栏（R10 AC2、AC3）。
- 网页经度 bug 在 `client-prepare.mjs` 里打补丁修掉（R10 AC4）。

### 2.5 安卓包（M5）

- **打包脚本**：原脚本只能在 Windows 跑（PowerShell + `.exe`），这台 Mac 也没装 Android 工具。M5 写一份 Mac 能跑的 `tools/android-build.mjs`，流程照原脚本：解包 → 打补丁 → 回包 → 对齐 → 签名 → 校验。
- **签名**：新建项目签名钥匙，放源码目录外。测试机要先卸载旧版一次。
- **选图和拍照**：新增 smali 桥。
  - 相册用系统选图（`ACTION_GET_CONTENT image/*`），不需要存储权限。
  - 拍照用系统相机，输出到 APP 缓存目录（加 FileProvider）。
  - 拿到的图在原生层缩到 512px，转 base64 交给接入层，再走同一个上传接口。
- **定位权限**：进大厅时申请，拒绝也能玩。
- **热更新**：
  - APP 启动先拉服务器上的接入层清单（文件地址 + sha256）。
  - 下载后校验哈希，通过才用；拉不到或校验不过就用 APK 里自带的那份。
  - 以后改界面只更新服务器上的脚本，不用重装。

## 9. 执行方式

单线做，不并行：服务端 `rooms.ts`、`original-wire.ts` 和接入层 `standalone.js` 是几个里程碑都要改的公共文件，并行容易互相覆盖。M5 的 smali 桥相对独立，到时可交给一个子智能体，只改 `client/android/native/` 下自己的文件。

## 10. 开工前的问题

1. **项目还不是 git 仓库**。A：先在本机 `git init` 做一次基线提交，只在本机，不推送（每一步改动都能看、能退）/ B：不用 git。建议 A。
2. **安卓打包工具**。A：M5 时我写 Mac 能跑的打包脚本，你点一条命令装 Android 打包工具和 apktool（从 Google 和 apktool 官方下载，约 300MB）/ B：回到原开发者那台 Windows 电脑上，用原脚本打包 / C：安卓先不做，网页版验收完再说。建议 A。
