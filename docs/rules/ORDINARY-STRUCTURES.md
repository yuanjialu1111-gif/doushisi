# 普通牌组合识别

组件版本：`dou14-ordinary-structures-v1`。源码：`apps/server/src/game/ordinary-melds.ts`。

这是一部分基础判胡所需的结构识别，不是完整地区引擎，不会自动解锁任何玩法。

## 依据及边界

外部来源为2017年360问答页面的扑克斗十四正文，地址`https://wenda.so.com/q/1488378970203390`。本轮重新访问并核对原文，已有完整网页快照保存在原项目工作区`work/research-next/wenda.html`，SHA-256为`80fc80c4869d1836236c03589050298b496b7c1aa8a85e060b2607b80a075835`。

正文描述两张凑14、同数字三张碰和四张杠，也明确限制碰必须摆到桌面才成为完成组合。该文是外部版本，不是本APK完整地区规则；没有因此批准其中所有发牌、王、付款或番数规定。

原APK普通卡面编码已在`research-chat-followup`核对为101至113、201至213、301至313、401至413。组件从这些普通编码取1至13作结构数字，不把A/J/Q/K的分值、王的排序值或UI候选转发当作本算法。

## 实现

- 吃的结构候选：A/K、2/Q、3/J、4/10、5/9、6/8、7/7，可跨花色。每组恰好两张实体牌。
- 碰的结构候选：三个普通牌数字相同。
- 杠的结构候选：四个普通牌数字相同。
- 候选保留每张实体牌ID，同牌面不同副本不会合并。实体牌重复引用直接报错。
- 输入顺序不影响输出；组合生成不重复枚举排列。
- 传入一张来源牌时，只生成与它配对的单张手牌候选，不包含无关的手内组合。
- 王、白板及其他特殊图编码一律明确拒绝，不能被余数运算误当普通牌。
- 候选数量超限明确失败，不静默漏掉其他分解。

## 地区调用约束

调用方必须显式指定当前允许识别哪些组合。生成的碰/杠候选不代表当前阶段可以执行动作，更不能未经处理就传入手牌胡牌搜索。

例如外部普通模式的未落地三张5，不能因为生成器能识别“同点三张”就直接计为完成组合。地区引擎必须先处理起手、摆牌、补牌及动作顺序；对仅允许两张凑14的手内分解只启用`chi`。

生成器没有决定：吃谁的牌、响应优先级、过张、偷补、杠/巴条件、王替代、是否必须全手成组、组数门槛、红黑点、听牌或付款。输出也没有`legalWin=true`字段。

## 测试

19个独立结构案例位于`cases/ordinary-melds-v1.json`。另有6项测试覆盖所有普通数字与花色组合、同点多张选择、现有精确覆盖搜索、来源牌身份、非法输入与候选上限。

已验证5、5、9只产生两个可选的两张吃，不能用同一张9覆盖三张手牌；5、5、9、9存在两种不重用实体牌的覆盖。四个7有6种两张结构、4种三张结构和1种四张结构，实际采用何种动作仍由地区规则裁决。

`tools/test/ordinary-source.test.mjs`核对原网页快照哈希、关键结构条款及“碰须落地”的限制，不将通过结果写成地区完整规则已验证。
