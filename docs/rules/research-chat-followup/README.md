## 四彩二精的原代码链

1. 原提取 `FrameGameConfig.js:3394` 的编号 22 选项，`siCaiErJing=1` 的提示为“四个七当彩电，大小王当精直接沉，每张算一番”。提示本身此前已在配置书收录，本次新增的是它与资源分支的关联。
2. 原 `assets/assets/dss/index.js:4432` 的 `dss_tools.getCard` 仅在 `areaType=EN_AREA_TYPE_PKDDS_ZTYJ`、`siCaiErJing` 为真、输入为 `107/207/307/407` 之一时，从 `resmap` 取 `1004`；否则取输入编码同名资源。提取文件对应 `dss_tools.js:17`。
3. `dssboot.loadRes` 在原 `dss/index.js:4479` 加载 `res/cards` 的 SpriteFrame，随后以资源名建立 `resmap`。该加载链确认这里选择的是图像。
4. 以无网络、无场景入口的最小资源和房间替身执行原 `getCard`，覆盖 2 个区域、开关两值及 7 个输入，28 项断言通过。盐津四个 7 在开启时都返回字符串 `1004`，关闭或其他地区恢复原编码。它没有改写输入牌编码或牌堆。

这条分支明确禁止把 `1004` 的存在当作“另加一种实体牌”的直接证据。它也不证明彩电可以参与哪些组合、如何计红黑点或何时必须沉牌。

## D04、D05 的边界

本次未找到新增完整组合/判胡算法或红黑点计分函数。原结算排序器 `dss_settle_UIController.cmatch_card` 对仅含 `1007` 或 `1012` 的单元素数组直接返回，位置为原 `dss/index.js:4191`；该语句此前已被算法摘录收录。这里只核对了其对应的图像，不能由特殊排序推出特殊胡型。

D05 现在可以明确普通编码对应的视觉花色和红黑颜色，但仍不能把视觉颜色等同于服务端计点；尤其 Joker 和橙色特殊图的计点仍未知。J/Q/K 在图像上呈字母，不提供“每张 1 点”算法证据。D03、D04、D05 均保持用户要求的“继续找证据，暂不定稿”。
