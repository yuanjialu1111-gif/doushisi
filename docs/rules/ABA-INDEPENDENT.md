# 阿坝斗十四独立规则 v1

日期：2026-09-24。配置：`9:0`。版本：`aba-independent-v1`。配置`10:0`、`11:0`、`12:0`各有同规则体系的版本化实现，分别见对应发布规则书。

定稿依据：[用户全部自动批准](INDEPENDENT-APPROVAL.md)。原包明确写出的选项与文字优先；未由原包直接证明的部分是开发方独立定义，不宣称等同原服务器。

## 牌堆与结构

普通牌为四花色A至K各一张，共52张。阿坝原包没有王数选择，本版固定加入小王、大王各1张，白皮2张，共56张实体牌。

白皮按原包`baipiType=1`默认名称“直接摸上手”，本独立实现明确沿用原有`bonus + replacement`：白皮作为特殊牌移入奖励区，再补普通牌，不把它作为普通牌留在暗手，也不因加入外置模式改写该默认。`11:0`另按下节定义`baipiType=2/3`，不能再以“独立版只实现1”为由拒绝开房，也不能把2/3静默归一为1。此补充针对`11:0`，不据此宣称`9:0`、`10:0`、`12:0`的外置模式已经通过验收。

普通结构为四组：两张凑14、同点三张碰/偷、同点四张杠/巴；余下暗手逐两张凑14。报叫、胡牌和付款都只由服务端判胡器计算。

## 11:0 外置白皮的独立定义

| 选项 | 处理与使用权限 |
| --- | --- |
| `baipiType=1` | 原包名称为“直接摸上手”；原有`bonus + replacement`将白皮移入奖励区并补牌，不作为普通牌保留暗手，不建立外置白皮响应窗口。 |
| `baipiType=2` | 白皮不上暗手，公开外置并记录翻出者；仅该玩家可以利用它偷、吃、碰、杠、胡，其他玩家不能响应使用。 |
| `baipiType=3` | 白皮不上暗手，公开外置并记录翻出者；翻出者及其他玩家均可利用它偷、吃、碰、杠、胡，但仍须选择服务端实际提供的合法候选，并非无条件可胡。 |

- 白皮的实体牌ID、来源座位和所属公开区进入服务端快照；存在合法候选时才记录对应响应候选及窗口ID。2/3的响应资格不由`quanXing`改变；该选项继续单独约束7及既有王的处理。开房冻结的`baipiType`、`quanXing`、底分和独立规则版本在后续各轮与重连中保持一致。
- 外置白皮用于补足普通组合中的一张牌：吃为一张真实普通牌加白皮；白皮所有者本人用它加两张同点普通牌时，可选择`tou`（偷）或`peng`（碰），保留两种候选但必须二选一，两者同优先级、同计分；其他玩家的同类候选只能是`peng`，不能偷别人的白皮。杠为三张同点普通牌加白皮。胡牌替代也必须落到完整的合法四组结构。它不是另造一张普通牌，也不允许同一实体白皮重复占位或同时执行偷与碰。
- 白皮明组（吃、偷、碰、杠）候选仅在可接牌的等待手长提供：`fullSize = 8 - 2 × 已完成明组数`，实际暗手张数必须为`fullSize - 1`，并满足明组数量及普通牌组合限制。已有`fullSize`张普通暗手的玩家不能再接白皮明组，不能通过虚增手长获得候选。
- 有合法候选才开启共用响应窗口，先裁决胡，再裁决杠、碰/偷、吃；同级非胡冲突按来源后的座位顺序。2只收集自己的合法响应，3收集所有符合候选的玩家；过牌/超时结束本次机会，不产生白皮奖励分。没有任何合法候选的白皮直接自动过弃，实体移入弃牌区并继续待续任务，不建立空窗口；不能声称模式2每张白皮都必定开窗口。
- 开局先处理所有玩家手中的特殊牌并完成相应补牌，将需要接牌的手规范为等待手，再对有合法候选的外置白皮开启窗口，不让未处理的特殊牌残留在可行动暗手中。多个外置白皮按队列逐张处理：当前张完成窗口裁决或无候选自动过弃后，才处理下一张，并按当时最新手长重新生成候选。起手或补牌的未完成任务保留在快照中，不能跳过未裁决窗口。
- 庄家若已有8张普通牌，保留首弃权，暂不提供外置白皮接牌候选，以`openingDealerPending`记录这项待续首弃。其他玩家使用开局白皮并完成组合、补牌后保留待弃权；若还有白皮先继续逐张处理，进入正常行动时由当前使用者先弃牌。之后行动顺序轮到庄家时，庄家直接弃牌，消耗待续首弃，不能重复摸牌再弃。
- 连续白皮可先后由不同玩家使用；已完成组合和补牌、暗手达到`fullSize`但尚欠一次弃牌的玩家，逐一记入`pendingDiscards`队列保留待弃权。处理后续白皮时不能覆盖或丢掉前一玩家的待弃状态。行动顺序轮到队列中的玩家时直接弃牌并消耗该次待弃权，不能再摸一张；庄家的待续首弃同样不能被重复执行。
- 连续两张白皮算例：模式2中所有者吃首张后已满手，第二张若没有合法胡或其他候选，就自动过弃而不再开窗口，所有者的待弃权仍保留。模式3中第二张可由仍为`fullSize - 1`等待手的其他玩家使用，前一使用者的满手和`pendingDiscards`待弃状态仍保留；不能为继续接白皮把满手玩家重新当作等待手。
- 组合获准后按实际组合大小补足使用者暗手；全过则白皮归入弃牌区并恢复该次待完成的起手/补牌任务。普通翻牌全过时继续正常行动顺序。补牌连续翻出白皮也逐张处理；无牌可补时按流局结束，不能凭空补牌。
- 白皮胡获准后，将实际使用的实体白皮移入公共`won`区；多个赢家在胡牌结构中只引用该实体ID，不各自复制白皮。明组获准则移入使用者明组区，全过移入弃牌区，三者都只是实体迁移。
- 整副牌始终是52张普通牌加4张特殊牌（小王1、大王1、白皮2），共56张实体牌。每个ID只能存在于一个区域；外置、弃置、进入明组或`won`区均不得复制、丢失或重新发牌。牌堆顺序、待补任务、`openingDealerPending`、`pendingDiscards`和已提交响应应能从持久化快照恢复；重连只能看到自己的暗手及公开区，不暴露他人暗手或牌堆顺序。

## 分数制

本版采用独立定稿的分数制。该规则统一适用于`9:0`、`10:0`、`11:0`和`12:0`：

- 两张凑14组按其两张普通牌红点之和×10计结构分。
- 同点三张碰/偷按该点红点×10计分，杠/巴按×15计分。
- 小王、大王以及`baipiType=1`按既有`bonus + replacement`路径处理的白皮，每张在奖励区计100结构分，不作为普通暗手或替代牌保留。
- `11:0`的`baipiType=2/3`外置白皮不进奖励区，不因翻出或使用直接增加红分、黑分、结构分，也不能把所替代普通牌的花色/点数算作实际分数。含白皮的普通组合只按其中真实普通牌计红黑点和对应结构分；其他真实奖励牌仍按原规则计分。
- 结构分达到`huRedScore`（300/400/500）才可胡牌。起胡线仅由`huRedScore`决定，`playerNum`不缩放；该门槛在`9:0`、`10:0`、`11:0`和`12:0`四个配置中均按绝对结构分计算。`playerNum`只决定入座、发牌和结算人数；同一合法手牌在2、3、4人配置下使用相同的分数线。
- 最终单份金额 = 底分 × `结构分 / 100` × `2^封顶后番数` × `0.8`。

该公式和系数来自D11的通用回退文字，开发方在本版明确采用；它不是原服务器实测。

外置白皮计分算例：红桃5加白皮代9的吃组，只计真实红点5、黑点0及50结构分，白皮不另加100分，也不追加所代9的点数；黑桃5加白皮代9则红点0、黑点5、该组红结构分0。两张实际红5加白皮的碰组按实际红点10计100结构分，不按三张红5虚增至150分。

双进双出的“四七”按最终胡牌结构中的四张不同实体普通7判定。暗手与明组的每个普通7实体ID只计一次，不能把同一明组7重复累加；白皮不是普通7，即使替代7完成组合也不计入“四七”，更不能从特殊牌编码误读出普通牌点数。两张真实7加白皮不等于三张真实7，三张真实7加白皮也不触发“四七”条件。其他成立条件仍须按既有独立规则另行判断。

先汇总番数，再按`maxFan`封顶；未开启的玩法不引入番数。

## 报叫

`baojiaoCondition=1`：已有结构分达到起胡分少100即可报叫。

`baojiaoCondition=2`：已有结构分达到起胡分才可报叫。

`baojiaoCondition=3`：已有结构分达到起胡分的一半即可报叫，报叫后加1番，最终胡牌仍须达到起胡分。

报叫后锁定听口，不另设失败罚分。
